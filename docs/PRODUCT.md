## 1. 프로젝트의 출발점

「쉼」은 사용자를 앱 안에 오래 머물게 만드는 서비스가 아니다. 힘들고 지친 순간, 사용자가 지금의 생각과 장소에서 잠시 거리를 두고 온전히 자신에게 집중할 수 있도록 '작은 쉼'을 빠르게 실행해주는 서비스다.

우리가 생각하는 쉼은 문제를 해결하거나 상담을 대신하는 것이 아니다. 지금 당장 해결하기 어려운 문제로부터 3분, 5분, 10분, 20분 정도 잠시 떨어져 나와 나 자신에게 돌아올 수 있는 여백을 만드는 것이다.

### 핵심 목적
힘든 순간, 누구나 지금 있는 곳에서 잠시 생각과 환경으로부터 거리를 두고 온전히 자신에게 집중할 수 있는 작은 쉼을 제공한다.

### 브랜드 철학
> "잠시 모든 것에서 벗어나, 오롯이 나만을 위한 시간을 갖는 것. 그것이 우리가 생각하는 쉼이다."

### 제품 원칙
- 사용자를 오래 붙잡지 않는다.
- 사용자가 해야 할 행동은 최소화하고, 앱이 해줄 수 있는 것은 최대한 대신한다.
- 조언보다 실행이 먼저다.
- 쉼이 끝나면 사용자를 현실로 돌려보낸다.
- 의료·상담·치료 서비스가 아니라 일상적인 휴식 실행 서비스로 설계한다.

---

## 2. 해결하려는 문제

사람은 힘든 순간에 '쉬어야 한다'는 사실을 알아도 실제로 무엇을 해야 할지 결정하기 어렵다. 산책을 하려면 음악을 고르고, 타이머를 맞추고, 알림을 끄고, 어디로 갈지 생각해야 한다. 지친 상태에서는 이 선택 과정 자체가 부담이다.

기존 명상·웰니스 서비스는 콘텐츠 탐색과 앱 내 체류를 요구하는 경우가 많다. 「쉼」은 반대로 사용자가 최소한의 입력만 하면 앱과 AI가 그 순간에 필요한 환경을 구성하고, 가능한 빠르게 화면에서 벗어나게 하는 것을 목표로 한다.

### 핵심 문제 정의
> "힘든 순간에는 쉬는 방법을 선택하고 준비하는 것조차 어렵다."

따라서 「쉼」의 역할은 쉬라고 말하는 것이 아니라 '지금 이 사람에게 필요한 몇 분'을 설계하고 실행하는 것이다.

---

## 3. 핵심 사용자 경험

1. 사용자가 앱을 연다.
2. 사용자는 현재 상태를 한 번의 탭 또는 짧은 문장으로 표현한다.
   - 예: "머리가 너무 복잡해", "사람에게 지쳤어", "아무것도 하기 싫어", "그냥 10분 쉬고 싶어"
3. 앱은 필요한 경우에만 최소한의 추가 정보를 확인한다.
   - 예: 사용 가능한 시간, 실내/외 여부, 이동 가능 여부
4. AI가 현재 상태와 개인 선호, 시간, 위치, 날씨, 기기 연결 상태 등을 바탕으로 쉼 계획(Rest Plan)을 만든다.
5. 사용자는 큰 버튼 하나를 누른다 — **"쉼 시작"**
6. 이후 앱이 가능한 범위에서 자동으로 환경을 바꾼다.
   - 음악 또는 자연음 재생, 타이머 시작, 화면 밝기 조정, 앱 화면 최소화, 선택된 방해 앱 제한, Watch 안내 및 진동 등
7. 쉼이 진행되는 동안 사용자는 휴대폰을 거의 보지 않는다.
8. 종료 시 짧게 현재 상태만 확인한다 — "조금 나아졌어요 / 그대로예요 / 더 불편해요"
9. 이 피드백은 다음 쉼을 개인화하는 데 사용한다.

---

## 4. 제품의 핵심 문장

- 기존 AI의 역할: "산책해보세요."
- 「쉼」의 역할: **"10분 동안 내가 환경을 정리해줄게요."**

「쉼」은 **추천 앱이 아니라 실행 앱**이다.

---

## 5. AI의 역할 — AI Rest Director

AI는 휴대폰을 직접 조작하지 않는다. AI는 사용자의 상태를 이해하고 어떤 쉼 시나리오를 실행할지 결정하는 '쉼 디렉터'다.

### 기본 구조
```
사용자 → 쉼 앱 → 상태 분석 → Rest Engine → AI Rest Director
      → Safety/Rule Check → Rest Plan → iOS 기능 실행
```

### AI가 담당하는 영역
- 사용자의 자연어 이해
- 현재 상태와 피로 유형 분류
- 적절한 쉼 유형 선택
- 쉼 시간과 순서 결정
- 음악 또는 사운드 유형 선택
- 개인 사용 기록을 반영한 개인화
- 사용자에게 보여줄 짧은 안내 문구 생성

### 앱과 OS가 담당하는 영역
- 실제 음악 재생
- 타이머
- 로컬 알림
- 화면 밝기
- 위치 취득
- Apple Watch 통신 및 햅틱
- 허용된 범위의 Screen Time 제어
- 사용자 데이터 저장

AI는 명령을 자연어가 아닌 **구조화된 Rest Plan**으로 반환한다.

```json
{
  "duration_minutes": 10,
  "rest_type": "environment_reset",
  "audio": "calm_acoustic",
  "movement": "slow_walk",
  "brightness": 0.25,
  "watch_guidance": true,
  "screen_mode": "minimal",
  "end_checkin": true
}
```

앱은 이 결과를 **검증한 뒤** 허용된 기능만 실행한다.

## 6. Rest Engine

AI에게 모든 판단을 맡기지 않는다. 서비스 품질과 안전성을 위해 규칙 기반 Rest Engine을 AI 앞뒤에 둔다.

### Rest Engine의 역할
- 사용 가능한 쉼 블록 관리
- 사용자의 현재 환경에 맞지 않는 행동 제거
- 시간대와 이동 가능성에 따른 제약 적용
- 기기에서 실제 실행 가능한 기능만 선택
- 과거 만족도에 따른 추천 우선순위 조정
- AI가 생성한 결과를 실행 전 검증

### 초기 Rest Blocks 예시
`WALK` / `MUSIC` / `NATURE_SOUND` / `BREATHING` / `STRETCH` / `SILENCE` / `DARK_SCREEN` / `WATCH_GUIDE` / `NO_PHONE` / `SHORT_REFLECTION`

### 예시 규칙
- 운전 중에는 화면을 계속 봐야 하는 행동을 제안하지 않는다.
- 야간에는 각성을 높이는 강한 활동을 기본 추천하지 않는다.
- 사용 가능 시간이 매우 짧으면 장거리 이동형 쉼을 제외한다.
- 비가 오는 경우 실외형 쉼의 우선순위를 낮춘다.
- 사용자가 반복적으로 낮은 평가를 준 쉼 블록은 우선순위를 낮춘다.

---

## 7. 개인화 구조

사용자의 과거 전체 대화를 매번 AI에 전달하지 않는다. 개인화에 필요한 정보를 우리 서비스의 데이터베이스에서 구조화해 관리한다.

### 사용자 프로필 예시
- 선호: 음악 높음, 걷기 높음, 명상 낮음
- 선호 시간: 8~15분
- 빈번한 상태: 업무 후 인지 피로, 사회적 피로
- 높은 만족도 조합: 음악 + 걷기
- 낮은 만족도 조합: 긴 음성 가이드, 긴 글쓰기
- 최근 쉼 결과: 10분 걷기 + 음악 '조금 나아짐'

AI에는 현재 판단에 필요한 최소 정보만 전달한다.

장기적으로 축적해야 할 핵심 자산은 "어떤 상태의 사람에게 어떤 쉼 조합이 실제로 도움이 되었는가"에 대한 익명화·집계 데이터와 개인별 선호 데이터다.

## 8. iOS 우선 구현 전략

첫 개발 플랫폼은 iOS로 한다. 웹은 아이디어 검증이나 관리 도구에는 사용할 수 있지만, 우리가 정의한 핵심 경험은 네이티브 iOS 기능이 필요하다.

| 기능 | 판단 | 비고 |
|---|---|---|
| 음악 재생 | 구현 가능 | MusicKit `ApplicationMusicPlayer` / `SystemMusicPlayer`. Background Audio capability 설정 시 백그라운드 재생 가능 |
| 타이머 및 종료 알림 | 구현 가능 | 앱 내부 타이머 + 로컬 알림 조합 |
| 위치 | 구현 가능, 권한 필요 | Core Location. 정밀 위치 장기 저장보다 '실내/외, 집 근처, 회사 근처, 이동 중' 수준으로 가공 |
| 화면 밝기 | 구현 가능하나 동작 특성 고려 | `UIScreen.brightness` 0.0~1.0. 기기 잠금 시까지 유지되며 잠금 해제 후 시스템 설정값으로 복원됨. **원래 밝기 복원 로직을 신중히 설계** |
| Apple Watch | 구현 가능 | watchOS 앱/연동으로 남은 시간·짧은 안내·햅틱. HealthKit은 명시적 동의 전제로 향후 검토 |
| 방해금지/Focus 자동 제어 | **핵심 설계 전제로 삼지 않음** | 일반 서드파티 앱이 시스템 전체 Focus를 임의 제어하는 구조로 제품 핵심을 설계하지 않는다. Shortcuts/Focus 연계는 별도 옵션 |
| Screen Time 기반 앱 제한 | **가능성 보유, MVP 핵심에서 분리** | FamilyControls / ManagedSettings / DeviceActivity. 권한·entitlement·App Store 정책 검토 필요. MVP 성공 조건을 여기에 의존시키지 않는다 |
| 기기 잠금 | **불가를 기본 전제** | 일반 앱이 iPhone 자체를 강제 잠그는 기능은 요구사항에서 제외 |

## 9. iOS MVP 기능 범위

MVP의 목적은 모든 자동화를 한 번에 구현하는 것이 아니라 "AI가 설계한 짧은 쉼을 사용자가 실제로 실행하고 다시 사용하는가"를 검증하는 것이다.

### MVP 필수 기능
- 간단한 온보딩
- 현재 상태 선택 또는 한 줄 입력
- 쉼 시간 선택 또는 AI 자동 결정
- AI 상태 분석
- Rest Plan 생성
- Rest Engine 검증
- 자체 사운드/음악 또는 MusicKit 기반 오디오 재생
- 쉼 타이머
- 어두운 최소 화면
- 화면 밝기 제어
- 로컬 종료 알림
- 쉼 종료 후 1회 피드백
- 사용자별 기본 선호 저장

### MVP 이후 우선 기능
- Apple Watch 햅틱 및 짧은 안내
- 위치/날씨를 활용한 상황별 쉼
- Apple Music 개인 취향 반영
- Screen Time 기반 방해 앱 Shield 기술 검증
- 사용자 패턴 기반 자동 추천
- HealthKit 연동 검토

## 10. 첫 번째 대표 사용자 흐름

1. 사용자가 앱을 열고 "머리가 너무 복잡해"를 선택한다.
2. 앱은 "10분 정도 나에게 맡길까요?"라고 제안한다.
3. 사용자가 '쉼 시작'을 누른다.
4. AI와 Rest Engine이 '음악 + 천천히 걷기 + 화면 최소화 + 10분 타이머'를 선택한다.
5. 앱이 음악을 재생하고 화면 밝기를 낮춘다.
6. 화면에는 남은 시간과 한 문장만 남긴다 — "휴대폰은 내려놓고 천천히 걸어보세요."
7. 사용자는 앱을 보지 않고 10분을 보낸다.
8. 종료 시 알림 또는 햅틱으로 돌아올 시간을 알려준다.
9. 사용자가 한 번만 평가한다 — "조금 나아졌어요."
10. 서비스는 이 결과를 다음 추천에 반영한다.

## 11. 기술 아키텍처 초안

```
iOS App (Swift / SwiftUI)
  ↓
Backend API
  ↓
Auth / User Profile / Rest History
  ↓
Rest Engine
  ↓
AI Gateway
  ↓
OpenAI API (초기)
  ↓
Structured Rest Plan
  ↓
Safety & Rule Validation
  ↓
iOS Execution Layer
```

AI Gateway를 OpenAI 전용으로 강하게 결합하지 않는다. 향후 비용, 성능, 정책 변화에 따라 다른 모델을 선택할 수 있도록 모델 호출부를 추상화한다.

초기에는 OpenAI API를 사용하되, 사용자가 늘어도 개별 사용자가 ChatGPT 계정을 공유하는 구조가 아니다. 앱 서버가 API를 호출하고 사용자별 정보와 기록은 우리의 시스템에서 분리 관리한다. **API Key는 iOS 앱 바이너리에 직접 포함하지 않고 서버에서 관리한다.**

## 12. 데이터 원칙

- 개인화를 위해 필요한 최소 데이터만 수집한다.
- 정밀 위치를 불필요하게 장기 보관하지 않는다.
- 원본 대화 전체를 영구 기억으로 사용하는 구조를 피한다.
- 사용자의 민감한 상태 입력은 저장 필요성과 보존 기간을 별도로 정의한다.
- 분석용 데이터는 가능한 익명화·집계한다.
- 사용자가 자신의 기록을 확인하고 삭제할 수 있는 구조를 향후 제공한다.

---

## 13. 안전 경계

「쉼」은 일상적인 휴식과 환경 전환을 돕는 서비스다. **의료적 진단, 정신건강 치료 또는 위기 상담을 대체하지 않는다.**

사용자의 입력에 자해·자살 등 즉각적인 위험 가능성이 감지되는 경우 일반 Rest Plan 생성 흐름과 분리된 **Safety Flow**로 전환해야 한다. 이 영역은 단순 생성형 AI의 자유 판단에 맡기지 않고 별도 정책 및 안전 설계를 적용한다.

---

## 14. 성공 지표

일반 앱처럼 체류시간을 핵심 KPI로 삼지 않는다.

- 쉼 시작률
- 쉼 완료율
- 쉼 이후 '조금 나아짐' 비율
- 동일 사용자의 재사용률
- 추천된 쉼과 실제 완료 행동의 일치율
- 사용자별 선호 학습에 따른 만족도 개선
- 앱 화면을 보지 않고 쉼을 완료한 비율

### 핵심 North Star 후보
> "쉼을 완료한 뒤 사용자가 이전보다 조금 나아졌다고 응답한 횟수."

## 15. 당장 만들지 않을 것

- SNS형 피드
- 사용자 간 경쟁/랭킹
- 과도한 출석 체크와 게임화
- 긴 AI 상담 채팅
- 콘텐츠를 끝없이 스크롤하게 하는 구조
- 처음부터 복잡한 커뮤니티
- 모든 웨어러블 동시 지원
- AI가 사용자의 모든 결정을 대신하는 구조

이 기능들은 '사용자를 앱에서 빨리 벗어나게 한다'는 제품 철학과 충돌하거나 MVP 검증에 필요하지 않다.

## 17. 현재 제품 결정 사항

- 제품명(가칭): **쉼**
- 첫 플랫폼: **iOS**
- 초기 AI: **OpenAI API**
- 핵심 인터페이스: **최소 입력 + '쉼 시작' 버튼**
- AI 포지션: **상담사가 아닌 AI Rest Director**
- 제품 포지션: **추천이 아니라 실행**
- 서비스 목표: **앱 체류가 아니라 현실에서의 짧은 쉼**
- 장기 핵심 자산: **개인별 쉼 선호 + 쉼 조합 효과 데이터 + Rest Engine**
